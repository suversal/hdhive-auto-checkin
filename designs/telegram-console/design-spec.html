SHIKE / PRODUCT DESIGN

给重复的小事，
安排一个好时间。

拾刻（暂定名）是一个开源、自部署的 Telegram 自动任务工具。设计围绕一个简单的问题展开：用哪个账号，在什么时间，向哪个会话，做哪件事。

进入交互原型 →体验首次设置体验创建任务
产品原则页面结构核心流程任务配置状态与异常视觉规范响应式与可访问性开发交接
01 / PRODUCT PRINCIPLES

把复杂留在系统里，把选择留给用户。

产品范围：单管理员、多 Telegram 账号、自己的服务器或 NAS。现有 GitHub Actions 脚本继续作为独立入门方案。当前交付是前端交互原型，尚未连接真实 Telegram、服务端调度或认证。

先让第一条任务跑起来

不在首页展示技术配置。新用户先接入账号，再选择模板；时间、通知和重试使用清晰默认值。高级功能在需要时展开。

动作说人话

使用“执行账号”“目标会话”“消息内容”“什么时候执行”。Cron、代理、StringSession 都有明确入口，避免成为必填门槛。

结果有证据

执行状态与业务判定分开。“收到回复”不等于“签到成功”。失败解释发生在记录详情里，并给出下一步行动。

最重要的体验：新用户能独立创建第一条任务，并读懂它的执行结果。
02 / INFORMATION ARCHITECTURE

页面少一点，路径清楚一点。

日常导航只有概览、任务、账号、记录、模板。设置和帮助保持次级位置。登录和首次设置使用独立布局，任务编辑使用完整页面，短操作使用弹窗，执行详情使用侧边抽屉。

页面 / 路由用户要解决的问题主要内容与行为
首次设置
#setup		我如何开始？设置空间名称和管理密码 → 填写 Telegram API 信息 → 添加账号 → 选择首个模板。允许暂时跳过添加账号，随时返回空间。
登录
#login		如何安全进入面板？单一管理密码，支持粘贴和密码管理器；密码错误就地提示；忘记密码提供服务器侧恢复说明。
概览
#overview		今天安排了什么，有没有问题？已开启任务、今日执行、需要留意；接下来执行的任务；账号状态；最近记录。空状态显示明确的第一步，不显示空指标。
我的任务
#tasks		如何管理已有安排？全部 / 已开启 / 已暂停；搜索和账号筛选；开关、立即执行、编辑、复制、导出、删除。
新建 / 编辑任务
#new		如何把需求变成可执行任务？四步向导，持续显示配置预览。编辑复用同一表单，保留原 ID、执行历史和计划开关状态。
任务详情
#task/:id		这件事具体如何执行？账号、目标、顺序步骤、结果规则、时间计划；配置和执行记录两个页签；支持暂停和编辑。
账号
#accounts		用谁发送，账号还可用吗？手机号登录 / 导入已有会话；账号名称、脱敏手机号、状态、关联任务数；检查连接、重新登录、移除。
执行记录
#runs		实际发生了什么？搜索、结果与日期筛选；执行时间和耗时；抽屉内展示原文、发送状态、执行过程、处理建议；支持复制与导出。
任务模板
#templates		有没有现成配置？文字签到、带按钮签到、群提醒、周期查询、每周备忘。使用模板后仍需确认自己的账号、目标和时间。
设置
#settings		如何调整系统偏好？通用、Telegram 连接、通知、安全与数据四类。高级连接参数从日常任务中移走。
帮助与入门
#help		我遇到了不理解的地方。重新体验设置、查看模板、常见问题。帮助文案直说含义，避免给用户堆协议与实现细节。
03 / CORE FLOWS

从第一次进入，到每天不必再管。

首次使用
启动实例→设置管理密码→连接 Telegram→添加账号→选择模板→创建并开启
创建一条任务
选择方式→账号与目标→操作内容→时间与确认→任务详情→可选：立即执行
处理一次异常
概览提示 / 通知→执行详情→确认是否已发送→处理连接或核对会话→决定是否再次执行

登录账号

  1. 填写账号别名和带国家区号的手机号。
  2. 验证码在 Telegram 客户端或其他 Telegram 指定渠道接收。
  3. 仅在需要时显示两步验证密码。
  4. 成功后回到原页面，不丢失正在编辑的任务。

导入与分享

  1. 导出的是纯任务模板。
  2. 模板不含账号凭证、Session、Token。
  3. 导入后任务默认暂停。
  4. 重新选择账号、确认目标，再手动开启。

编辑与删除

  1. 编辑保留既有配置。
  2. 未保存离开时允许继续编辑或放弃。
  3. 删除任务前解释后续计划将停止。
  4. 历史执行记录独立保留。
04 / TASK EDITOR

一次只做一组决定。

步骤默认暴露交互与校验
1. 选择方式发送消息 / 消息＋按钮；模板入口每种方式都有一句具体解释。选按钮方式时生成常用顺序步骤，用户可以继续调整。
2. 账号与目标名称、执行账号、目标会话默认选第一个可用账号；最近会话支持名称选择；支持 @用户名、ID、收藏夹；正式版在保存前解析目标身份与权限。不可用账号显示重新登录入口。
3. 操作内容发送消息、等待回复、点击按钮顺序列表，支持上移、下移、移除和添加。第一步先发消息，点击按钮前等待回复。消息空白、超过 4096 字符、按钮未填写时就地报错。
4. 时间与确认每天固定时间、时区、通知、保存后启用也可选每周、间隔、单次与 Cron。预览未来三次执行；最后用一句话复述谁向谁做什么。保存本身不触发立即执行。
进阶设置默认收起成功 / 失败关键词、随机延迟、恢复与限流策略说明。未填成功条件时显示原文，不能显示为业务成功。
时间必须让人看得懂。
每天 08:30 与时区同时展示；随机时间明确写为“计划时间后再延迟 0–N 分钟”。每周可以多选星期；单次任务执行后结束计划。Cron 是进阶选项，正式版需用服务端解析与返回的未来执行时间作为最终依据。原型以 2026/11/09 10:42 为固定示例时钟，预览未来 15 天。

没有账号

创建入口引导先接入账号；也能先浏览模板。添加账号弹窗关闭后仍停留在原页面。

按钮来自当前消息

用文字定位当前收到的按钮；不要永久复用旧的 callback data。重复同名按钮应报歧义，提示更具体的选择方式。

仅发送消息

群提醒或收藏夹备忘可以移除等待步骤。系统只记录消息发送结果，不以“没有回复”判失败。

05 / STATES & RECOVERY

说清发生了什么，再说接下来怎么办。

已发送

仅发送任务完成

消息发送得到确认。本任务不要求回复，不推断其他业务状态。

已收到回复

有回复，业务结果未判定

展示原始文字；没有匹配规则时保持这个状态，避免误报成功。

规则匹配成功

命中用户设置的成功规则

显示命中哪一条关键词，失败关键词优先。同一回复有冲突时明确提示。

规则匹配失败

业务回复命中失败规则

消息执行可能正常，但业务失败。正式版分别保留传输状态和业务判定。

等待回复超时

已发送，结果不确定

先提示查看对应会话。不会无条件自动重发；再次执行前提示可能重复操作。

执行异常

按错误类型提供行动入口

账号失效→重新登录；网络失败→检查连接；无权限→更换目标；限流→显示可恢复时间。

关键边界

情况系统行为用户看到的内容
账号会话失效暂停该账号执行，不阻塞其他账号；保存任务配置。“需要重新登录”，提供直接入口。重登后不会补发全部历史任务。
Telegram 限流尊重 FloodWait；将等待与恢复时间持久化；按账号隔离。“Telegram 要求等待，预计 HH:mm 继续”，不承诺随机延迟能规避风控。
同一账号同时到点同一账号进入串行队列；同一任务的手动 / 定时执行互斥。“排队中”，显示前面还有几项；按钮不能连续生成重复运行。
机器人多条 / 编辑回复关联本次发送后的目标消息与消息编辑事件；等待匹配的结果，不抓任意群消息。步骤日志保留匹配依据；无法唯一对应时显示结果未确认。
服务重启错过计划默认跳过过期触发，恢复下一次；可在后续版本增加有截止时间的补执行。记录“错过计划，已跳过”，避免服务恢复时集中发送。
移除账号暂停关联任务并清除绑定；清除本实例的会话；业务记录脱离账号继续保留。移除确认中列出受影响任务数，并解释如何在 Telegram 撤销会话。
通知失败通知状态与任务结果分开；通知故障不触发业务消息重发。“任务已执行，通知发送失败”，单独提供重发通知操作。
正在编辑时离开内部导航和关闭页面均提示；正式版还需恢复非敏感草稿。“继续编辑”作为主操作，“放弃修改”作为次操作。

加载用局部骨架或按钮忙碌状态；表单错误靠近字段并移动焦点；空状态始终有下一步；保存反馈短暂显示且不遮住操作。账号错误和等待超时是主要原型异常路径，更多网络错误需在真实服务接入后验证。

06 / VISUAL LANGUAGE

暖白、墨绿，和恰到好处的留白。

浅色界面作为第一版主视觉。墨绿只用于主操作、选中状态和品牌；暖灰负责层级，柔和蓝色表示“收到回复”，琥珀色表示需留意。用文字与图标配合颜色，不把控制台变成仪表盘拼盘。

文字

中文优先系统字体，英文使用 Avenir Next 等系统后备，无远程字体依赖。页面标题 24–27px，分组标题 15–18px，桌面常规控件 13–14px，手机输入框 16px；10–11px 仅用于非关键辅助标签。正式版对不熟悉技术的用户可增加“舒适字号”偏好。

空间

4 / 8px 基准。桌面侧栏 222px，内容边距 40px，卡片间距 20–24px，卡片内边距 24–30px。桌面主按钮 42–44px，手机主按钮至少 44px，内容圆角 14px、控件圆角 8px。克制阴影，只为弹层服务。

图标与动效

一致的 1.65px 线性 SVG 图标，不用 emoji 充当导航。状态变化 160–200ms，执行反馈表达进度。没有自动滚动、装饰性闪烁和阻挡操作的入场动画，尊重减少动态效果偏好。

07 / RESPONSIVE & ACCESSIBLE

手机上也能配置，不只是缩小一张桌面。

场景布局处理交互要求
宽桌面 ≥ 1190侧栏＋主内容；概览使用主列表与辅助时间线两列；编辑页固定配置摘要。主内容有最大宽度，不让文字在超宽屏上无限拉长。
平板 761–1190保留侧栏；概览辅助区折为下方；编辑摘要在窄列不足时收起。表格保留必要字段，避免主操作滑到看不见的位置。
手机 ≤ 760五项底部导航；完整导航可从顶部展开；任务表格变为卡片；步骤保持单列。摘要合并到最后确认区，底部导航不遮挡按钮；尊重设备安全区。
弹窗与抽屉桌面居中弹窗 / 右侧详情；手机接近满宽，内容可独立滚动。焦点进入弹窗并受约束，Escape 关闭，退出回到触发控件。
键盘与读屏真实按钮、表单标签、导航地标、开关状态和错误关联。可见焦点，所有操作支持键盘；拖动均有上移下移替代；反馈使用状态播报。
长内容 / 大字会话地址允许换行，卡片能增高；缩放不能禁用。关键说明不用省略号截断；不依赖 hover 才能发现操作；需以真实浏览器做大字及触屏验收。
验收重点：375px 手机、768px 平板、1440px 桌面；任务创建全流程；空白空间；验证码错误与两步验证；超时后的处理建议；保存 / 复制 / 暂停 / 删除；模板导出和导入；无控制台异常；减少动态效果下功能完整。
08 / HANDOFF

设计定清楚，开发有边界。

原型采用本地 React 运行文件、编译后的 JavaScript 和 CSS，预览不依赖 CDN。演示任务与非敏感偏好保存于当前浏览器，可从顶栏“交互原型”菜单恢复示例或切换空白空间。验证码、密码、Token、API Hash、Session 均不持久化。

原型已覆盖

主要页面和导航；任务完整向导与校验；顺序步骤；时间预览；任务操作；账号接入演示；执行与异常演示；模板；设置；首次引导；手机适配。

真实系统需实现

服务端认证与会话、限流登录、凭证加密、Telegram 登录和会话解析、按钮匹配、数据库调度、运行互斥与恢复、通知、升级与备份。服务端重新校验全部输入。

后续版本再评估

AI 识图、自动回复、消息监控转发、群话题、多分支流程与插件。第一版以稳定、易上手的常用任务闭环为发布目标。

开发时必须保持的契约

  1. 区分账号连接状态、执行传输状态和业务判定，不用一个布尔成功值承载三者。
  2. 保存任务、开启计划、立即执行是三个不同动作；“测试”如果会真实发消息，必须明确说明。
  3. 未来执行时间由服务端调度规则返回；Web API 多进程不能重复启动调度器。
  4. 不把真实登录会话或管理员 Token 保存在前端演示使用的 localStorage 模式中。
  5. 给前端稳定的错误类型与可重试语义，避免向用户直接抛出堆栈和原始凭证字段。
  6. 远程使用面板需完整认证、HTTPS、CSRF / 来源校验与访问限制；未初始化实例不能被匿名抢先接管。
  7. 验证所有离开编辑器的导航拦截、未保存草稿和运行中断行为；原型已覆盖取消、内部导航与关闭页面时的保护。
  8. 自定义目标、频道权限、回调按钮与历史 Session 的兼容性，以真实 Telegram 集成验收为准。
