## 实现约定

- SQLite 是任务和记录的唯一数据源，浏览器不保存登录会话或管理凭证。
- 登录 Session 与 API Hash 加密保存，加密密钥独立于数据库；管理密码只存慢哈希。
- 管理员仅能在部署端通过交互终端创建，网页只提供登录。已移除首次设置口令和公开初始化 API；日常使用管理密码、HttpOnly 会话 Cookie 和 CSRF 校验。
- 单实例运行调度器；任务定义和下次执行时间持久化；同账号串行执行。
- 保存、开启、立即执行为不同操作。消息已发送后等待超时，不自动重复发送。
- 原始回复与业务判定分开；成功关键词未命中时不假报业务成功。
- 登录、按钮、限流、重启恢复均有可替换 Telegram 适配器测试；生产入口始终使用真实适配器。

## 11 月 10 日：普通消息的回复等待修复

用户测试发现普通账号消息发送后仍显示超时。只读检查确认，该记录为 `sent=true`、`sendState=sent`、`REPLY_TIMEOUT`，任务包含发送和等待回复 60 秒两个步骤；原因是普通消息向导也默认附加了等待步骤。

- 新建普通消息默认只有发送步骤，增加明确的“等待对方回复”开关；需要机器人回复时主动开启，按钮及签到模板保留原有等待流程。
- 编辑旧任务时保留原始步骤，不按接收方类型静默修改；关闭等待开关保留消息草稿。复杂流程继续逐步编辑。
- 配置预览及发送前确认显示是否等待回复，执行日志明确记录“消息已发送”和等待时限；超时状态改为“已发送 · 未等到回复”，提供关闭等待的操作指引。
- 系统完成提示不再写入原始回复字段，实际回复为空时保持为空；已发出或结果不确定的消息仍不自动重发。
- 后端 55 项测试通过，涵盖无回复的普通账号、收藏夹、Bot，以及明确等待时的超时和不重复发送。隔离浏览器验证默认值、开关、草稿保留和手机布局；不向真实账号追加测试消息。
